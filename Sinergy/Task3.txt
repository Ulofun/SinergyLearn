Проектирование реляционной базы данных предполагает чёткое определение структуры таблиц, отношений между ними и назначение ключевых полей. Рассмотрим структуру базы данных «Туризм», включающую справочники и основную таблицу переменных данных.

### Структура базы данных

#### Таблицы-справочники (таблицы постоянной информации):

1. **Страны**
   - Хранит список стран, предлагаемых туристическим агентством.
   - Первичный ключ: `id`

| Поле       | Тип           |
|------------|---------------|
| id         | INTEGER PRIMARY KEY AUTO_INCREMENT |
| country_name | VARCHAR(100) UNIQUE NOT NULL |

Пример данных:
| id | country_name     |
|----|------------------|
| 1  | Россия           |
| 2  | Турция           |
| 3  | Греция           |

---

2. **Типы туров**
   - Список возможных типов туристических предложений (экскурсионный тур, пляжный отдых, экскурсионно-пляжный и т.п.).
   - Первичный ключ: `id`

| Поле      | Тип           |
|-----------|---------------|
| id        | INTEGER PRIMARY KEY AUTO_INCREMENT |
| tour_type | VARCHAR(100) UNIQUE NOT NULL |

Пример данных:
| id | tour_type          |
|----|--------------------|
| 1  | Экскурсионный      |
| 2  | Пляжный            |
| 3  | Горнолыжный        |

---

3. **Категории размещения**
   - Категория отеля/гостевого дома, такие как категория гостиницы («эконом», «стандарт», «люкс»).
   - Первичный ключ: `id`

| Поле               | Тип           |
|--------------------|---------------|
| id                 | INTEGER PRIMARY KEY AUTO_INCREMENT |
| accommodation_category | VARCHAR(100) UNIQUE NOT NULL |

Пример данных:
| id | accommodation_category |
|----|------------------------|
| 1  | Эконом                |
| 2  | Стандарт              |
| 3  | Люкс                  |

---

4. **Услуги**
   - Перечень дополнительных услуг, предлагаемый туристическому пакету (страховка, трансфер, экскурсии).
   - Первичный ключ: `id`

| Поле   | Тип           |
|--------|---------------|
| id     | INTEGER PRIMARY KEY AUTO_INCREMENT |
| service_name | VARCHAR(100) UNIQUE NOT NULL |

Пример данных:
| id | service_name   |
|----|----------------|
| 1  | Страхование    |
| 2  | Трансфер       |
| 3  | Питание        |

---

#### Основная таблица переменной информации (связывающая остальные таблицы):

5. **Заказ тура**
   - Содержит всю необходимую информацию о заказе конкретного туристического пакета.
   - Внешние ключи связаны с предыдущими таблицами.
   - Первичный ключ: `order_id`

| Поле                   | Тип                     |
|------------------------|-------------------------|
| order_id               | INTEGER PRIMARY KEY AUTO_INCREMENT |
| customer_name          | VARCHAR(100) NOT NULL |
| country_id             | INTEGER FOREIGN KEY REFERENCES Countries(id) |
| tour_type_id           | INTEGER FOREIGN KEY REFERENCES TourTypes(id) |
| accommodation_category_id | INTEGER FOREIGN KEY REFERENCES AccommodationCategories(id) |
| services_ids           | TEXT                    |
| total_cost             | DECIMAL(10,2) DEFAULT 0 |
| booking_date           | DATE                    |

Связанные поля (внешние ключи):
- `country_id`: ссылка на страну назначения.
- `tour_type_id`: ссылка на тип выбранного тура.
- `accommodation_category_id`: ссылка на категорию размещения.
- `services_ids`: строка с ID выбранных услуг (например, перечисленные через запятую).

Пример данных:
| order_id | customer_name | country_id | tour_type_id | accommodation_category_id | services_ids | total_cost | booking_date |
|----------|---------------|------------|--------------|---------------------------|--------------|------------|--------------|
| 1        | Иванов Петр    | 2          | 1            | 2                         | 1,2          | 50000.00   | 2025-05-15   |

---

### Связи между таблицами:

1. Между таблицей заказов и странами (**Many-to-one**) – один заказ относится к одной стране.
2. Между таблицей заказов и типом тура (**Many-to-one**) – один заказ принадлежит одному типу тура.
3. Между таблицей заказов и категорией размещения (**Many-to-one**) – один заказ привязывается к определенной категории проживания.
4. Услуги хранятся отдельно, и связь с заказом осуществляется через строку с перечнем ID услуг.

Эти отношения позволяют эффективно управлять информацией о заказах и предоставляют возможность расширять функциональность системы путем добавления новых категорий, услуг и маршрутов.

### Заключение:
Предложенная структура позволяет хранить разнообразные типы туристических продуктов, формировать заказы клиентов и поддерживать гибкость расширения функциональности сервиса туризма.
